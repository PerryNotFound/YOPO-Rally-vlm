# 常见问题

## 仿真相关

**Q：启动后 Unity 无法连接？**

检查 `ros_tcp_endpoint` 是否正常启动（默认监听 `0.0.0.0:10000`）。确认 Unity 中填写的 IP 地址和端口与 ROS2 机器一致，防火墙需开放 10000 端口。

**Q：RViz2 中看不到候选轨迹？**

确认发布目标点后 YOPO 节点有正常输出（查看 `/end_state` 话题是否有消息），并在 RViz2 中添加了对应的 Path 显示（`/visualize/path_0` 至 `/visualize/path_4`）。

**Q：机器人不动，MPC 没有输出？**

MPC 节点需要同时收到 `/end_state`（来自 YOPO）和 `/odom` 才会触发规划。检查里程计话题是否正常发布，以及 YOPO 节点是否已接收到目标点。

## 训练相关

**Q：运行 `generate_data.py` 时 CloudCompare 相关步骤报错？**

确认已安装 CloudCompare 2.13+，并且其可执行文件路径已加入系统 `PATH`（Flathub 版本通常为 `flatpak run org.cloudcompare.CloudCompare`）。检查 `cloud_compare.py` 中的调用命令是否与本机安装路径一致。

**Q：训练时提示找不到 `data_opt.toml`？**

必须先运行 `generate_data.py` 生成优化标签，再运行训练脚本。每个 Scene 都需要对应的 `data_opt.toml`，否则该 Scene 会被跳过。

**Q：CasADi 轨迹优化部分帧失败？**

部分帧（如起点在障碍物附近）可能无法收敛，这些帧会被自动跳过，不影响整体训练流程。若失败率过高，检查 `configs.py` 中的速度和扇形角度约束是否与仿真器的运动范围匹配。

**Q：训练收敛慢或损失不下降？**

确认使用了虚拟环境中的 PyTorch（支持 CUDA），通过 `torch.cuda.is_available()` 验证。也可适当降低学习率或增大批大小。

## 实车部署相关

**Q：T265 里程计漂移导致规划不稳？**

T265 长距离使用存在累积误差。可启动时加 `vins:=true` 切换为 VINS-Fusion 视觉惯性里程计，或在机器人底盘上集成 IMU 融合方案。

**Q：OAK-D 深度图分辨率与训练不匹配？**

YOPO 节点会自动将输入深度图 resize 到 160×32，无需手动调整相机分辨率。确认 OAK-D 发布的是对齐后的深度图话题（`/oak/stereo/image_raw`）。

**Q：MPC 跟踪有抖动？**

可在 `mpc_node.py` 顶部适当降低 `vel_out_multiplier`（如调至 0.7～0.8），或增大控制代价权重以抑制角速度振荡。

**Q：切换模型后效果变差？**

确认使用的模型与当前代码版本匹配（输出通道数一致）。不同训练实验的模型在配置上可能有差异，切换时需同步检查 `candidate_num`（候选数，默认 5）等参数。
