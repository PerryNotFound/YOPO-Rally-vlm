# 实车部署

## 硬件配置

| 设备 | 型号 | 说明 |
|------|------|------|
| 机器人底盘 | Diablo | 两轮自平衡机器人，通过 `diablo_ctrl` ROS2 包控制 |
| 深度相机 | OAK-D Pro | 提供双目深度图，话题 `/oak/stereo/image_raw` |
| 视觉里程计 | Intel T265 | 提供 6-DOF 位姿与速度，话题 `/camera/pose/sample` |
| 算力平台 | Jetson Xavier NX（推荐）或带 CUDA 的笔记本 | 运行推理节点 |

## 启动流程

### 完整启动命令

```bash
ros2 launch diablo_ros_wrapper diablo_depolyment.launch.py
```

**可选参数：**

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `gui` | `true` | 是否开启 RViz2 可视化 |
| `ctrl` | `false` | 是否启动底盘驱动节点（`diablo_ctrl`） |
| `depthai` | `false` | 是否启动 OAK-D 相机驱动 |
| `vins` | `false` | 是否启动 VINS-Fusion 里程计（替代 T265） |

典型启动命令（开启底盘驱动与相机）：

```bash
ros2 launch diablo_ros_wrapper diablo_depolyment.launch.py ctrl:=true depthai:=true
```

## 节点架构

```
T265 → /camera/pose/sample ──┐
                              ├─► DepolymentMsgConvertor ──► /odom
OAK-D → /oak/stereo/image_raw ┘
                │
                ▼
          yopo_node（YOPO 推理）
                │
                ▼
          mpc_node（MPC 跟踪）
                │
          /cmd_vel ──► DepolymentMsgConvertor ──► /diablo/MotionCmd ──► 底盘
```

## 消息转换节点

节点文件：`src/ros_pkgs/diablo_ros_wrapper/diablo_ros_wrapper/depolyment_msg_convertor.py`

该节点承担两项工作：

**里程计转换**：将 T265 以自身坐标系发布的位姿转换为标准 `base_link` 坐标系下的 `/odom` 话题，供 YOPO 节点和 MPC 节点使用。

**控制指令转换**：将规划器发出的 `geometry_msgs/Twist`（`/cmd_vel`）转换为底盘驱动所需的 `motion_msgs/MotionCtrl` 格式，发布至 `/diablo/MotionCmd`。

同时，该节点以硬编码方式广播各传感器的静态 TF（`map → odom → base_link → {t265, oak-d-base-frame}`），如传感器安装位置有变动需修改对应的平移向量。

## 路点跟踪模式

节点文件：`src/ros_pkgs/diablo_ros_wrapper/diablo_ros_wrapper/waypoint_tracker_node.py`

该节点可在预设路点列表中按顺序发布目标点，无需手动在 RViz2 中操作。路点以 `[x, y, yaw]` 格式在节点文件顶部的 `WAYPOINTS` 列表中配置。

## MPC 节点说明

YOPO 节点输出最优轨迹的终点状态（位置 + 速度），MPC 节点在此约束下求解低层速度指令序列，以 20 Hz 发布 `/cmd_vel`，规划时域为 10 步（步长 0.25 s）。

速度范围约束：线速度 ±2.0 m/s，角速度 ±π rad/s。输出速度可通过 `mpc_node.py` 顶部的 `vel_out_multiplier` 参数缩放（默认 1.0）。
