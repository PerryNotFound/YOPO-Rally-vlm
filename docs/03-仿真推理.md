# 仿真推理

## 概述

本工程通过 [ROS-TCP-Endpoint](https://github.com/Unity-Technologies/ROS-TCP-Endpoint) 将 ROS2 与 Unity 仿真器连接，在仿真中测试地形规划。

## 启动流程

### 1. 启动 YOPO-Sim

启动 YOPO-Sim，切换到对应的测试场景（`Assets\Scenes\EvaluationScene`）。

### 2. 启动 ROS2 端

```bash
ros2 launch diablo_ros_wrapper diablo_sim.launch.py
```

`diablo_sim.launch.py` 会依次启动三个子模块：

| 子模块 | 作用 |
|--------|------|
| `ros_tcp_endpoint` | 监听 Unity 消息（默认端口 10000），桥接为 ROS2 话题 |
| `diablo_algorithm` | 启动 YOPO 推理节点与 MPC 节点 |
| `diablo_visualize` | 启动 RViz2 可视化（可通过 `gui:=false` 关闭） |

### 3. 在 Unity 中连接

在仿真器界面点击 **Connect** 按钮，输入 ROS2 机器的 IP 地址与端口（默认 10000）。

### 4. 开始规划

在 RViz2 中使用 **2D Pose Estimate** 工具点选目标位置，MPC 节点即开始跟踪 YOPO 输出的最优轨迹。

## YOPO 推理节点

节点文件：`src/ros_pkgs/diablo_ros_wrapper/diablo_ros_wrapper/yopo_node.py`

**订阅话题：**

| 话题 | 类型 | 说明 |
|------|------|------|
| `/camera/depth/image` | `sensor_msgs/Image` | 深度图，自动 resize 至 160×32 |
| `/odom` | `nav_msgs/Odometry` | 位置与速度 |
| `/goal_pose` | `geometry_msgs/PoseStamped` | 目标位置 |

**发布话题：**

| 话题 | 类型 | 说明 |
|------|------|------|
| `/end_state` | `nav_msgs/Odometry` | 最优轨迹终点（供 MPC 跟踪） |
| `/visualize/depth_nn` | `sensor_msgs/Image` | 预处理后的深度图 |
| `/visualize/path_0` ~ `/visualize/path_4` | `nav_msgs/Path` | 5 条候选轨迹（可视化用） |
| `/visualize/path_min_cost` | `nav_msgs/Path` | 最低代价轨迹 |

## MPC 节点

节点文件：`src/ros_pkgs/diablo_ros_wrapper/diablo_ros_wrapper/mpc_node.py`

MPC 节点以 20 Hz 运行，规划时域为 10 步（步长 0.25 s），订阅 `/end_state` 和 `/odom`，发布 `/cmd_vel` 速度指令。

## 关键配置参数

训练路径和模型路径在 `src/diablo_project/configs.py` 中统一配置：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `YOPO_SIM_Path` | `/home/chy/Downloads/YOPO-Sim_Linux` | YOPO-Sim 根目录 |
| `load_model_path` | `models/yopo_net.pth` | 推理模型路径 |
| `trained_model_folder` | `models/temp` | 训练输出目录 |

YOPO 节点的推理参数（推理频率、规划时长、候选轨迹数等）在节点文件顶部配置。
